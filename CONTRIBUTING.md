## Contribution workflow

1. Read the project [`LICENSE`](LICENSE), especially sections 3.5 and 6.
2. Fork or clone the official repository only as needed to prepare a pull request.
3. Privately build and run your modified version only as needed to develop and test the proposed
   contribution. Repository-hosted continuous integration may do the same.
4. Keep the change focused and explain what it changes, why it is useful, and how it was tested.
5. Identify third-party material and its licence. Do not submit material you do not have the right
   to provide.
6. Submit the change as a pull request. Only the Owner decides whether it is changed, merged,
   released, or rejected.
7. Do not publish or deploy a modified game build. Delete a contribution-only fork or branch within
   a reasonable time if the Owner requests it after the pull request is rejected, closed, or
   withdrawn.
